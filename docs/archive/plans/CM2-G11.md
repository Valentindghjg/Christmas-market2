## Goal
A player claims a 7-day daily reward streak (into the active save, 2× for group members once the owner sets a group ID) and a board of 3 rotating quests plus a bonus per save, each claimed manually and once, from a new "Quests" panel.

## Design decisions (engineering, record in DECISION_LOG)
| Topic | Decision |
|---|---|
| Daily streak owner | Per **player** (profile `daily`), paid into the **active save**; one claim per player and UTC day across saves and servers (co-op members claim their own). |
| Day | `floor(businessClock / 86400)` (UTC). Claimed yesterday → next index; missed ≥ 1 full day → back to day 1; after day 7 → day 1 (PROVISIONAL). Clock behind `lastDay` → `AlreadyClaimed`. |
| Claim order | Validate → rate limit → in-flight guard → active, available save → group check (may yield) → profile `UpdateAsync` marks the day (atomic guard) → save still active → grant in the company critical section. Grant refused → revert exactly this claim; revert failed → `warn`, reward lost (at most once, never twice). |
| Group | `GroupId = 0` → hidden, never doubled, no `IsInGroup` call. Else `Player:IsInGroup` in `pcall` at join and each claim; error → cached value (default false). ×2 on cash and reputation inside the one claim. Join button: `GroupService:PromptJoinAsync` in `pcall`; membership may be cached per server, so the text says "from your next visit". |
| Quest board owner | Per **save** (`state.quests`, schema 21), progress from any member's actions. |
| Rotation | Windows `floor(clock / 14400)`. A stale board is replaced on the next note, claim or test hook; unclaimed rewards lapse. Progress grows only from play events, so offline time never pays. The view never mutates. |
| Counting | Orders: quantity of each successful `placeOrder`. Sales: each `completeReservedSale` (sale price, 1 tree, its size); pass/boost bonus not counted. Rewards are not revenue and get no cash multiplier. |
| Scaffold | `QuestService.lua`, its test, the old `GameConfig.Quests` and `questClaims` are replaced (never client-reachable). |

Company record, schema 21: `quests = {period: int >= 0, progress: {int x4}, claimed: {boolean x4}}` (index 4 = bonus). Migration 20 → 21 and the legacy-v1 path: `state.questClaims = nil; state.quests = QuestBoard.new(0)`; `BusinessState.new`: `quests = QuestBoard.new(0)`. Period 0 is stale, so the first access builds the current board.

Player profile (no `SaveProfile.VERSION` bump; precedent `tutorialOffered`, `lastPlotId`): optional `daily = { lastDay: int >= 0, streak: int 1..7 }`; nil = never claimed.

Player attributes: `DailyNext` (1..7, day the next claim pays), `DailyClaimable` (bool), `DailySecondsLeft` (to the next UTC day), `DailyGroup` (`Hidden`, `Join`, `Active`).

## Steps
1. **`src/shared/DailyRewards.lua`** (requires only GameConfig; `--!strict`):
   - `dayOf(now: number): number` = `math.floor(now / DaySeconds)`; `secondsLeft(now): number` = `DaySeconds - (math.floor(now) % DaySeconds)`.
   - `isValid(daily)`: nil, or exactly `lastDay` (integer >= 0) and `streak` (integer 1..#Days).
   - `status(daily, today): {claimable: boolean, nextIndex: number}`: nil → (true, 1); `lastDay >= today` → (false, `streak % 7 + 1`); `lastDay == today - 1` → (true, `streak % 7 + 1`); else (true, 1).
   - `claim(daily, today): (any?, number | string)`: not claimable → `nil, "AlreadyClaimed"`; else `{lastDay = today, streak = nextIndex}, nextIndex`.
   - `rewardFor(index, member): {cash, reputation, doubled}`: `Days[index]` × (`GroupMultiplier` if member else 1), `doubled = member`.
   - `groupState(groupId: number, member: boolean): string`: groupId 0 → `"Hidden"`, member → `"Active"`, else `"Join"`.
2. **`src/shared/QuestBoard.lua`** (requires GameConfig):
   - `periodOf(now)` = `math.floor(now / RotationSeconds)`; `new(period)` = `{period = period, progress = {0,0,0,0}, claimed = {false,false,false,false}}`.
   - `questFor(period, slot)`: slots 1–3 `Slots[slot][(period % 3) + 1]`, slot 4 `Bonus`; returns `{slot, kind, sizeId?, target, rewardCash, rewardReputation (default 0), textKey}` (`questOrderTrees`, `questSalesCash`, `questSell<Size>`, `questSellTrees`).
   - `isValid(quests)`: exactly `period` (integer >= 0), `progress` (4 integers 0..MaxProgress), `claimed` (4 booleans).
   - `refresh(state, now): boolean`: replaces `state.quests` by `new(periodOf(now))` when the period differs; returns whether it did.
   - `note(state, now, kind, amount, sizeId?)`: `refresh`; each unclaimed slot of this `kind` (same `sizeId` for SellSize) gets `progress = math.min(target, progress + amount)`; amount not a positive integer → ignored.
   - `noteSale(state, now, salePrice, sizeId)`: `note` SalesCash salePrice, SellTrees 1, SellSize 1 sizeId.
   - `claim(state, now, slot, period): (boolean, any)`: `refresh`; checks in this order `QuestsRotated` (period ~= current), `AlreadyClaimed`, `BonusLocked` (slot 4 before 1–3 are claimed), `Incomplete` (progress < target); then sets `claimed[slot] = true` and returns `(true, {slot, cash = rewardCash, reputation = rewardReputation})`. It never touches cash: QuestBoard must not require BusinessState (cycle); the mixin (step 6) pays and records.
   - `view(state, now)`: uses the stored board when its period is current, else `new(current)` (not stored); returns `{period, endsIn = (period + 1) * RotationSeconds - now, claimable = n, quests = {row x4}}`, row = def fields plus `progress`, `claimed`, `complete = progress >= target`, `locked = slot == 4 and not (claimed 1..3)`; `claimable` counts rows complete, not claimed, not locked.

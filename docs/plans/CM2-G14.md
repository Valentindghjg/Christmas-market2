## Goal
A delivery lands in its receiving bay by itself when the countdown over the bay reaches zero, while a truck pulls in beside the bays. The player walks to a bay, taps its prompt and stocks trees onto the lot with a touch-first bar: size, rotate, single place, row fill with gap control, and store mode, which puts a tree back into receiving. The server checks every spot: inside the lot, not too close to another tree, and clear of the checkout, parking, pickup row, bays, stand and spawn.

## Decisions (settled)
| Topic | Decision |
|---|---|
| Bay model | One order = one bay (OBSERVED: "Bays n/4", and orders are blocked when all 4 bays hold trees). No merging into another bay. A bay keeps its trees after arrival until they are stocked out, stored elsewhere or sold. A bay is **busy** when it holds trees or a pending order targets it. Bays persist in `state.bays`. `state.stock` is removed; the summary still exposes a derived `stock` map. |
| Bay ↔ order | `placeOrder` assigns the lowest free bay (`order.bay`) and sets its `speciesId`. At `dueAt` the server pass adds the quantity to `bays[order.bay].counts[size]` and removes the order. No player or Lot Worker unload step exists any more (OBSERVED: "The player does not unload"). |
| Unload countdown | `GameConfig.DeliverySeconds` 60 → **30** (OBSERVED range 25–31 s, §3.2). The countdown over the bay runs for the whole wait. The truck pulls in during the last `TruckPullInSeconds = 5` and leaves in `TruckLeaveSeconds = 3` (both PROVISIONAL, visual only). Deliveries are checked every `DeliveryPassSeconds = 1` (PROVISIONAL). |
| Manual unload | `Delivery.Unload`, `Inventory.Place` and `Inventory.Pickup` are removed from Protocol (they now return `UnknownAction`). `CompanyStateService:autoUnloadDeliveriesAll` and the "lot-worker unload" loop are removed. Server path for the Lot Worker (CM2-25/26): `PlacementService.stockFromBay` and `PlacementService.storeBack` are pure state functions without the hands check. CM2-25/26 will choose spots with `Stocking.check`. |
| Lot frame | Placements store `transform = {x, y = 0, z, rotation}`. Here `x` is the offset from the plot centre and `z` is the **depth toward the road** (+ = toward the road). World Z = `center.Z + facing · z`, where `facing = 1` if `center.Z < 0`, else `-1` (as `parkingOffset` already does). This makes a saved layout plot-independent. The world mirrors the stand, checkout, spawn and fences on plots 4–6 so that validation and world agree. Existing placements keep their numbers and are not re-validated. |
| Spot rules | Order: `OutsideLot` → `KeepClear` → `TooClose`. Each tree is a circle with radius `FootprintRadius[size]`. **Inside the lot** means the whole circle lies within x ±40, depth ≤ 27 and depth ≥ −27 − 6·level, where level = `clamp(progression.lotExpansion, 0, Progression.LotExpansion.maxLevel)`. **Keep clear** means the circle may not intersect any keep-clear box (closest-point distance < r). **Too close** means another tree's centre is nearer than `rA + rB − 0.01` (edges may touch). Legacy placements without a numeric `transform.x/z` are skipped. Coordinates are rounded to 0.01 on the server. |
| Row fill | The client sends `count` (1..10). Positions are `p_i = (x + i·s·cos θ, z + i·s·sin θ)` for i = 0..count−1, with `s = 2r + gap` and θ = rotation in degrees, each rounded to 0.01. The server validates all positions (and each against the earlier ones) before it changes anything: **all or none**. IDs are `"placement:" .. requestId .. ":" .. i` (i from 1, also for count 1). Idempotency comes from the persisted request ID (`DuplicateRequest`). |
| Store mode | Returns one unreserved displayed tree to the lowest-index bay of the same species with load < 9. If there is none, it goes to the lowest free bay; otherwise `NoFreeBay`. Then storage is checked (`StorageFull`). A reserved tree gives `Reserved` and is never moved. |
| Sell-back order | From receiving first: bays holding the SKU, **fewest of that SKU first**, ties to the lower index, so that bays free up. Then unreserved lot trees in sorted placement-ID order (unchanged). |
| Hands | `Stock.Place` and `Stock.Store` return `HandsFull` while the player carries a customer tree (OBSERVED: "needs empty hands"). |
| Ghost and labels | The ghost is client-only (a local model under `workspace.CurrentCamera`, for responsiveness). Bays, bundles, truck and the RESERVED label are built server-side in WorldService. The client reads bay contents from replicated attributes. |
| Migration overflow | Stock or pending orders that do not fit into 4 bays during 12 → 13 are refunded at wholesale (`cash +=`, one history entry `MigrationRefund`). No tree value is lost. |

**Schema 13** (`BusinessState.SCHEMA_VERSION = 13`; `GameConfig.VERSION` stays 1):
- `state.bays`: an array of exactly `Receiving.BayCount` (= `GameConfig.Receiving.BayCount`, 4) entries `{speciesId: string, counts: {[sizeId]: integer}}`. An empty bay is `{speciesId = "", counts = {}}`. `validate`: the array length equals BayCount and has no other keys; `speciesId` is `""` or a key of `GameConfig.Trees`; `counts` has only `SizeIds` keys with integers 1..1000; `speciesId == ""` implies empty counts. Capacity (9) is enforced only on mutation, never in `validate`, so no save gets locked out.
- `pendingOrders[*].bay`: integer. `validate` does not check it. `Receiving.normalize` repairs a missing or invalid value.
- `state.stock` is removed (`nil`); `validate` no longer reads it.
- Migration 12 → 13, inside the `migrate` chain: `state.schemaVersion = 13; applyStockMigration(state)`. The legacy V1 path also calls `applyStockMigration(state)` before `validated`. `applyStockMigration` does `local refund = Receiving.migrateStock(state); if refund > 0 then state.cash += refund; BusinessState.record(state, "MigrationRefund", refund) end`. Every load at schema 13 runs `Receiving.normalize(state)` after `pruneCompletedOrders`.
- Save size: 4 bays (≤ 300 B), ≤ 100 placements (`MaxPlacements`, unchanged), ≤ 100 history and request entries. The record stays below 30 KB.

## Steps
1. **`Receiving.lua`** (requires GameConfig, Inventory). `export type Bay = {speciesId: string, counts: {[string]: number}}`, `export type BayView = {index: number, speciesId: string, counts: {Small: number, Medium: number, Large: number}, total: number, arriving: number, arrivesIn: number}`.
   - `newBays(): {Bay}`. `bayTotal(bay): number`. `bayLoad(state, i): number` is the total plus the pending quantities with `order.bay == i`. `isBusy(state, i)` is load > 0. `freeBay(state): number?` is the lowest non-busy index. `usedCount(state)`. `storedTotal(state)`. `totals(state): {[sku]: number}` (new table). `count(state, speciesId, sizeId)`.
   - `add(state, i, speciesId, sizeId, n): boolean` fails if the bay is busy with another species, and sets `speciesId`. `take(state, i, sizeId, n): boolean` (exact count, removes zero keys).
   - `takeForSale(state, speciesId, sizeId, n): number` takes up to n, fewest of that SKU first, ties to the lower index, and returns how many it took.
   - `storeBay(state, speciesId): number?` follows the Decisions rule.
   - `normalize(state)`:
     - pads the bays to BayCount;
     - removes zero counts;
     - a non-busy bay gets `speciesId = ""`;
     - each pending order (sorted by orderId) whose `bay` is not an integer in range, or points to a bay whose `speciesId` differs from the order's, gets `freeBay` (setting its `speciesId`) or `nil` if none is free.
   - `migrateStock(state): number` (refund):
     - Delivered orders are added to the stock and removed.
     - Species go in `SpeciesOrder`, then other `GameConfig.Trees` keys sorted; sizes in `SizeIds` order. Each tree fills the current bay up to 9, then the next free bay.
     - Overflow is refunded at wholesale per tree. Unknown-species keys are dropped.
     - Then Pending orders, sorted by (dueAt, orderId), each get a free bay; if none is free, the order is refunded at wholesale × quantity and removed.
     - Finally `state.stock = nil`.
   - `view(state, now): {BayView}`: `arriving` is the sum of the pending quantities for the bay, `arrivesIn = max(0, min dueAt − now)`, or `-1` when nothing is arriving.
2. **`Stocking.lua`** (requires GameConfig). `radius(sizeId)`, `round(v) = math.floor(v * 100 + 0.5) / 100`, `facing(centerZ: number): number`, `rowPositions(x, z, rotation, sizeId, count, gap): {{x: number, z: number}}`. `layoutInput(state): {lotExpansion: number, trees: {{x, z, sizeId}}}` is built from `layout.placements` (with skips). `check(input, x, z, sizeId): (boolean, string?)`. `checkRow(input, positions, sizeId): (boolean, string?, number?)` returns the failing index. `Stocking.ErrorKeys` is the map in step 11.
3. **BusinessState**:
   - `new` gets `bays = Receiving.newBays()` and no `stock`.
   - `placeOrder` keeps its check order and replaces the `openOrderCount >= BayCount` check with `Receiving.freeBay(state) == nil → "NoFreeBay"`. On success it sets `order.bay`, sets `bays[bay].speciesId = species`, and returns `{orderId, cost, bay}`.
   - `reconcileDeliveries(state, t)` takes orders with `dueAt <= t`, sorted by (dueAt, orderId). For each: the bay is `order.bay` if valid, else `freeBay`; with no bay, the order stays pending. It runs `Receiving.add`, removes the order, `record("OrderUnloaded", 0)` and returns `true, delivered`.
   - `storageUsed` = `storedTotal` + pending quantities. `receivingSummary(state, now?)`: `baysUsed = usedCount` and adds `bays = view(state, now or 0)`.
   - Remove `unloadOrder`, `buyStock` and `sellStock`.
4. **Protocol**: `StockPlace = "Stock.Place"` with payload keys exactly `{bay, speciesId, sizeId, x, z, rotation, count, gap}`.
   - `bay` must be an integer 1..BayCount, else `InvalidBay`.
   - An unknown species gives `UnknownSpecies`; a bad size gives `InvalidSize`.
   - `x`, `z` must be finite with |v| ≤ CoordinateLimit; `rotation` must be an integer multiple of RotationStep in [0, 360); `gap` must be finite, within Min..Max, with `gap / Step` an integer. Any failure gives `InvalidPlacement`.
   - `count` must be an integer 1..RowMax, else `InvalidQuantity`.
   - Missing or extra keys give `UnexpectedField`.

   `StockStore = "Stock.Store"` takes `{placementId}`, a string of 1..96 characters, else `InvalidPlacementId`. Remove `DeliveryUnload`, `InventoryPlace` and `InventoryPickup` from `Actions` and `actionSet` (with their branches).
5. **PlacementService**:
   - `stockFromBay(state, idPrefix: string, bayIndex: number, speciesId: string, sizeId: string, x: number, z: number, rotation: number, count: number, gap: number): (boolean, any)`. It re-checks types and ranges (`InvalidPlacement`), then:
     1. a bay that is missing or holds another `speciesId` → `BayChanged`;
     2. `counts[size] < count` → `NotEnoughTrees`;
     3. placements + count > MaxPlacements → `PlacementLimit`;
     4. `Stocking.checkRow` fails → its code.

     Only then does it mutate: `Receiving.take`, add the placements, `Receiving.normalize`. It returns `{placementIds, bay, remaining = view counts}`.
   - `storeBack(state, placementId): (boolean, any)`:
     1. unknown placement → `UnknownPlacement`;
     2. reserved → `Reserved`;
     3. `storeBay` gives nil → `NoFreeBay`;
     4. `storageUsed + 1 > storageCapacity` → `StorageFull`.

     It then removes the placement, runs `Receiving.add` and returns `{placementId, bay}`.

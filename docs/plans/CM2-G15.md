Written by: `planner` (Opus 5.5, high). Implemented by: the agent for the tier below. Playtested by: `playtester` (Sonnet 5.5, medium). Reviewed and committed by: `reviewer` (Opus 5.5, medium). Pipeline: skill `cm2-task`.
Rule: everything below is decided. If something is missing, the implementer stops and reports; it never chooses.

## Goal
When a customer's tree is loaded (or the customer leaves without it), the customer leaves a 1–5 star review with a short text, based on the service time. Reputation from the review scales with the stars. The rating persists. Every plot shows a Part-built sign with the company name, the average stars and the likes. Another player can like a lot once per UTC day, never their own save.

## Decisions (reconciliation)
| Topic | Decision |
|---|---|
| Reputation at checkout | 0 (was +1). OBSERVED by arithmetic: the header table's totals only add up with 0 at checkout. New key `Customers.SaleReputation = 0`. |
| Reputation at loading | Replaces G1's `FastLoadSeconds` / `FastLoadReputation` / `SlowLoadReputation` (all three keys removed): gain = `Reviews.ReputationByStars[stars]`. |
| Service time | `queueSeconds + pickupSeconds`. `queueSeconds` = whole seconds from the NPC entering `Queued` to the sale (`visit.queuedAt`, os.clock), stored on the order (0 for the simulation/test path). `pickupSeconds` = `max(0, loadTime − order.soldAt)` on the business clock. |
| Review text | 5★ `reviewGreat`, 4★ `reviewGood`, 3★ and 2★ `reviewSlowService` when `queueSeconds > pickupSeconds`, else `reviewSlowTree` (both texts OBSERVED), 1★ `reviewVerySlow`. |
| Missed pickup (`expire`) | A 1★ review `reviewNoTree` that counts in the rating; the reputation penalty stays `MissedPickupReputationPenalty` (1). |
| Walk-outs and abandoned visits | No review: the customer never paid (reference reviews follow loading only). CM2-N2's observation (abandoned R 25/38, S 40/70 visits with 0 walk-outs, i.e. non-conversions) does not touch reviews; it goes to CM2-28 (balance pass). |
| Rating | Average of the last `RatingWindow` (50) review stars, shown with one decimal; "No reviews yet" when none. Lifetime `count` is kept too. |
| Likes | Lifetime total on the liked save. Set of today's likers on that save, reset when the UTC day changes (`floor(clock / 86400)`, business clock). Liker must play a save on this server (`CompanyReady`), be within reach of the sign, and not be in the target's `members` (owner or member) → `OwnLot`. |
| Like idempotency | Not recorded in `recentRequests` (that ring belongs to the target's own actions). The per-day set makes a replay return `AlreadyLikedToday`; no state changes twice. |
| Sign name | Broadcast-filtered save name while the owner (the name's author) is on this server (`filterName` in main.server, which refuses offline authors). Otherwise `"<owner username>'s Tree Lot"` (usernames need no filter), else "Tree Lot". Never the raw name. Filtered result cached per company and raw name. |
| Review popup | Server `Notify` toast to every player of the save: `tell(player, textKey, stars, orderNumber)`. It replaces the loader's `orderComplete` toast (key stays in Localization, no longer sent). |
| Sign place | Lot frame x 23, z 23 (Amendment 1; was x 31, which the decor fence at (34, 24) cut through): between the pickup row (z 10–16) and the front edge (z 27); the truck lane (x 46) is outside the lot. New KeepClear box `Sign`; existing placements inside it stay (N2 precedent). |

## Steps
1. **`src/shared/Reviews.lua`** (`--!strict`, requires `GameConfig`, `SaveProfile` via `script.Parent`; never `BusinessState`):
   - `Reviews.TextKeys = { reviewGreat = true, reviewGood = true, reviewSlowService = true, reviewSlowTree = true, reviewVerySlow = true, reviewNoTree = true }`
   - `newReviews() -> { count = 0, recent = {} }`; `newLikes() -> { total = 0, day = 0, today = {} }`
   - `isValid(state): boolean` checks both fields as in "Data and config".
   - `normalize(state)`: if `reviews.recent` is a table longer than `RatingWindow`, keep the newest `RatingWindow`; if `likes.today` holds more than `MaxLikesPerDay` entries, set it to `{}`. Tolerates missing or wrong types (no error).
   - `starsFor(serviceSeconds: number): number` per `StarMaxSeconds` (non-number or NaN → 1).
   - `textKeyFor(stars: number, queueSeconds: number, pickupSeconds: number): string` per Decisions.
   - `record(state, stars: number)`: append, drop from the front beyond `RatingWindow`, `count += 1`.
   - `ratingTenths(state): number?`: nil when `recent` is empty, else `math.floor(sum * 10 / #recent + 0.5)`.
   - `utcDay(timestamp: number): number` = `math.floor(timestamp / 86400)`.
   - `like(state, userId: number, day: number): (boolean, number | string)`: `state.members[userIdText] ~= nil` or `userId == state.ownerUserId` → `false, "OwnLot"`; if `likes.day ~= day` then `likes.day = day; likes.today = {}`; already in `today` → `false, "AlreadyLikedToday"`; `today` count ≥ `MaxLikesPerDay` → `false, "LikesFull"`; else add, `total += 1`, return `true, total`.
   - `starText(stars: number): string` = `string.rep("★", s) .. string.rep("☆", 5 - s)` (s clamped 1..5).
   - `signView(state) -> { saveName, ownerUserId, ratingTenths: number?, reviewCount = reviews.count, likes = likes.total }`.

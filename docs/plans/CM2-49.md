## Goal
On the first save a player plays, one-line hints with arrows guide them through ordering a tree, stocking it and checking out the first customer. The player can skip it. Progress is server-owned, survives a rejoin, and the tutorial never shows again for that save.

## Decisions
| Topic | Decision |
|---|---|
| Where progress lives | In the company save (`tutorial`, schema 18): one progress per save, shared by every member. The player profile only records whether the player was already offered a tutorial (`tutorialOffered`). |
| "First save only" | A new company record starts the tutorial only if its owner's profile has `tutorialOffered ~= true` when the record is created. Every owner play of any save sets `tutorialOffered = true`. So only the first save a player ever plays gets it. A player who already owned saves before this update gets none on new saves, and existing records migrate to finished. |
| Co-op | Members see the save's current step, also when they join mid-tutorial, and any member's action advances it. Any member may skip, which ends it for the whole save (every member may do every gameplay action, PRODUCT_SPEC). |
| Steps | `Order` → `Stock` → `Checkout` → `Done`. Events: a successful `BusinessState.placeOrder` sends `Ordered`; a successful `PlacementService.stockFromBay` (player or Lot Worker) sends `Stocked`; a successful `CustomerSimulationService.completeVisit` sends `Sold`. That covers the manual checkout through the N2 prompt, the Cashier and the headless simulation path. |
| Catch-up | An event completes its step and every earlier one. `Stocked` while on `Order` jumps to `Checkout`, and `Sold` on any step finishes the tutorial. Events for steps already done change nothing. So no state can get stuck. |
| Cashier | A fresh save has $84 and a Cashier costs $1,200, so the first checkout is manual. If a Cashier is hired anyway (Robux cash), the Cashier's sale completes `Checkout`. There is no special hint for that case. |
| Gameplay effect | None. The tutorial never blocks or changes an action. It only shows hints. |
| Skip | `Tutorial.Skip` on `BusinessAction`: empty payload, any member, idempotent by request ID, the standard per-action limit (10 per 10 s) plus the global limit. The client asks for a second tap within 3 s. |
| Client channel | Player attribute `TutorialStep` ∈ `Order`, `Stock`, `Checkout`, `Done`, `Skipped`, or nil without an active save. The server sets it on activation and after every change. |
| Device | One layout for all devices. The hint bar sits top-centre below the toast row, between the rail columns. Taps go through every overlay except Skip. |

## Data and config
- Company record, schema 18: `tutorial = { step = "Order" | "Stock" | "Checkout" | "Done", skipped = boolean }`. Valid only if `step` is one of the four, `skipped` is a boolean, and `skipped == true` only when `step == "Done"`. Extra keys are ignored.
- `BusinessState.new` → `{ step = "Done", skipped = false }` (off by default, so existing tests and fixtures stay unaffected). Migration 17 → 18 and the v1 path set the same value.
- New record with `options.tutorial == true` (PersistenceService) → `{ step = "Order", skipped = false }`.
- Profile field: `tutorialOffered: boolean?`. There is no `SaveProfile.VERSION` bump: old servers ignore the field and keep it on write. `SaveProfile.new` sets `false`. `validate` rejects a value that is neither nil nor a boolean.
- `UiTheme.TutorialBar = { maxWidth = 560, height = 56, padding = 6, skipWidth = 104, textSize = 15, arrowSize = 44, highlightPad = 4, worldArrowStuds = 6, refreshSeconds = 0.25, doneSeconds = 5, confirmSeconds = 3, displayOrder = 12 }` (PROVISIONAL).
- `RunPlaytest.BUILD = "cm2-49"`.

## Steps
1. **`src/shared/Tutorial.lua`** (`--!strict`, no requires):
   - `Tutorial.Steps = { "Order", "Stock", "Checkout", "Done" }`. `Tutorial.EventStep = { Ordered = "Order", Stocked = "Stock", Sold = "Checkout" }`.
   - `Tutorial.new(active: boolean)` → `{ step = if active then "Order" else "Done", skipped = false }`.
   - `Tutorial.isValid(value: any): boolean` implements the rule in Data.
   - `Tutorial.advance(state: any, event: string): boolean`. Returns false without a change if `state.tutorial` is invalid, the step is `Done`, or the event is unknown. Otherwise, with `i` = index of the current step and `e` = index of `EventStep[event]`: if `i <= e`, set `step = Steps[e + 1]` and return true; else return false.
   - `Tutorial.skip(state: any): (boolean, any)`. Invalid record → `false, "InvalidState"`. `Done` → `false, "TutorialDone"`. Else `step = "Done"`, `skipped = true` → `true, { step = "Done" }`.
   - `Tutorial.attribute(state: any): string?`. nil if invalid; `"Skipped"` if `Done` and skipped; else `step`.

## Steps
1. Write `docs/FRIENDS_TEST.md` in German (style of `docs/RELEASE_CHECKLIST.md`). UI text is quoted in English, copied verbatim from `Localization.lua` `en` for the key named below (`%s`/`%d` become `<Name>`, `<Zahl>`). Sections in this order:
   1. `# Freundestest (CM2-47a)` and a 3-line intro: 2–5 Tester, private Build, about 2 hours; roles **A** (the owner, host), **B**, **C** (needed for blocks C and X), **D**, **E** optional; at least one tester on a phone if possible. Roblox names never go into the repo (public); reports use A–E.
   2. `## Vorbedingungen (Owner)`, checkboxes:
      - V1 Studio-Queue-Batch passed (PC-7, "Next hasseln starts here" point 0): the client checks of CM2-25-26b, CM2-46b, CM2-49 are PASS.
      - V2 For block K: PC-8 done and CM2-46c (launch order 13c) committed, so the 12 products show "Buy". Without V2 block K is marked "nicht getestet"; everything else runs.
      - V3 Publish (owner only; engineering publishes nothing): `main` at a commit whose checks passed; Rojo connected; note `git log -1 --format=%h` in the result sheet; File → Publish to Roblox; keep it private, give the testers access in the Creator Dashboard (owner's choice how). Rollback: previous place version in the version history.
      - V4 Block X only: Creator Dashboard → experience → Places → the place → server size (max players) **2**; back to **12** after block X.
      - V5 Testers who never played this experience check the tutorial (the owner may have had it in Studio; Studio saves "Playtest …" in the owner's list can be deleted).
      - V6 Purchases cost **real Robux** on live servers (free only in Studio). The owner decides who buys. Suggested per buyer: CashPinecone 29, StarterPack 79, PassCashX2 99, BoostCashX2 10 (217 Robux).
   3. `## Ablauf`: one `###` per block in the order T, L, C, R, K, S, D, X; each a table `| Schritt | Wer | Aktion | Erwartet | Studio | Ergebnis |` with the rows of the step table below; `Ergebnis` empty (`☐ PASS ☐ FAIL ☐ nicht getestet`). Block S starts with "erst ab $1,200 (nach K3 oder nach D1)". Block X starts with V4 and "Wer auf welchem Server ist: Spielerliste (Tab)"; testers join via the Play button, not "Join friend".
   4. `## Studio-Abdeckung`: legend: `full NN` = step NN of `runPlaytest {mode="full"}`, `soak NN` = step of `runPlaytest {mode="soak", minutes=18}`; "nur live" = needs real clients or live servers; "nicht testbar" = not reachable with 2–5 players, covered by headless tests. Studio pre-run results: PROGRESS.md, CM2-47a.
   5. `## Nach dem Test`: reset server size (V4); the owner sends result sheet and bug reports in the chat; each FAIL becomes a fix task; go/no-go stays the owner's (2026-11-28).
   6. `## Fehlerbericht-Vorlage`: a fenced text block with fields: `Bericht-ID: B-<Nr>`, `Checklisten-Schritt:`, `Tester (A–E):`, `Gerät (PC/Handy/Tablet, System):`, `Server (mit wem auf demselben Server):`, `Uhrzeit (MEZ):`, `Spielstand (Solo/Duo/Trio/Quad, Owner/Member):`, `Was ich gemacht habe (Schritte):`, `Erwartet:`, `Passiert:`, `Text auf dem Bildschirm (wörtlich):`, `Screenshot/Video (ja/nein):`, `Wie oft (immer/manchmal/einmal):`, `Schwere (Blocker/Hoch/Mittel/Kosmetik):`, `Nur Owner – F9 → Server-Log (Fehlerzeilen):`. Then one line per severity: Blocker = test stops or progress/Robux lost; Hoch = feature wrong; Mittel = workaround exists; Kosmetik = look/text.
2. Add the TEST_PLAN item.
